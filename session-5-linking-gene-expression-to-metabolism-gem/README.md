# Hands-on Session 5: Student Bundle

This folder is the classroom distribution for the six computational precision-medicine exercises. It is intentionally separate from the instructor development tree.

## Contents

- `Exercise1_model_and_baseline_FBA/` through `Exercise6_validation/`: student worksheets only.
- `R/`: shared R model, medium, pathway, GPR, FBA/FVA, iMAT-like, knockout, validation, and native-screen runtime helpers.
- `config/`: only the versioned configuration files read by the worksheets and runtime workflows, including validation settings.
- `datasets_and_models/models/`: the original Recon1 reference and the adapted hands-on Recon1 biomass model.
- `datasets_and_models/treated/`: the preprocessed CSV inputs used by the worksheets. Raw source files and upstream preparation tools are not included.
- `scripts/export_context_sbml.py`: the narrow Exercise 2 SBML export helper. It is not a data-preprocessing script.
- `requirements.txt`: R, Quarto, and Python package requirements.

This distribution deliberately excludes instructor answer keys, handoff notes, tests, raw data, preprocessing scripts, rendered HTML/assets, and pre-existing `outputs/` directories. Outputs are created locally as students progress through the session.

## Execution order

Run commands from this directory so that project-root discovery and relative paths work.

1. Render or work through `Exercise1_model_and_baseline_FBA/Exercise1.qmd`.
2. Render or work through `Exercise2_expression_integration/Exercise2.qmd`. This creates the two context RDS files, two context SBML files, and QC tables consumed later. Rendering Exercise 2 also requires Python 3 with `cobra` and `pandas` for the SBML export helper.
3. Render or work through `Exercise3_pathway_and_flux_comparison/Exercise3.qmd`. It reads the Exercise 2 context files and creates its own analysis tables and figures.
4. Run the instructor-owned native single-gene screen before the native section of Exercise 4:

   `Rscript R/run_full_screen.R`

   Then render or work through `Exercise4_disease_selective_knockouts/Exercise4.qmd`. The toy knockout activity is generated by the worksheet; the native full-gene screen is intentionally a separate, potentially long computation.
5. Run the restricted native pair workflow before the native section of Exercise 5:

   `Rscript R/run_workflow.R`

   Then render or work through `Exercise5_synthetic_lethality/Exercise5.qmd`.
6. Run the Exercise 6 validation workflow and then render or work through `Exercise6_validation/Exercise6.qmd`:

   `Rscript -e 'source("R/exercise6_workflow.R"); exercise6_run()'`

The native screens are included because they are runtime analysis workflows, not upstream data preparation. They may take substantially longer than the classroom toy examples. Instructors can distribute precomputed checkpoints separately when classroom hardware or time limits make live execution impractical.

## Rendering

For a rendered HTML worksheet, use for example:

`quarto render Exercise1_model_and_baseline_FBA/Exercise1.qmd`

Repeat for the other five worksheets in order. Rendering writes HTML, Quarto asset folders, figures, and analysis outputs beside the source files; these generated files are intentionally absent from this clean distribution.

## Scientific scope

The models and settings are teaching resources. FBA objectives are conditional on the supplied model, objective, medium, and bounds; they are not experimental growth measurements. The expression and metabolomics tables are used according to the restrictions stated in the worksheets, and the healthy GTEx breast profile is not paired HMEC expression. Do not treat model outputs as clinical predictions.
